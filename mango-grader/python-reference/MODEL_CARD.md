# マンゴー表面等級判定モデル — アプリ組み込み用一式

## ファイル

| ファイル | 内容 |
|---|---|
| `mango_grader.py` | 特徴抽出＋判定のモジュール本体 |
| `mango_grader_model.joblib` | 学習済みモデル（178枚で学習） |

## 依存ライブラリ

```
opencv-python (cv2)
numpy
Pillow
scikit-learn
joblib
```

## 使い方

```python
from mango_grader import MangoGrader

grader = MangoGrader("mango_grader_model.joblib")
result = grader.predict("path/to/photo.jpg")

print(result["grade"])         # "A" / "B" / "C"
print(result["confidence"])    # 0.0-1.0
print(result["needs_review"])  # True なら人の確認を推奨
print(result["proba"])         # {"A":0.98, "B":0.01, "C":0.0}
```

複数枚まとめて処理する場合は `grader.predict_batch(path_list)`。

## 撮影条件について（アプリ化で一番大事な注意）

このモデルの閾値・重みは **2019年に撮影した178枚の条件に較正**されています。
無彩色の背景、単一果実、一定の距離・照明を想定しています。

アプリで撮る写真がこれと違う場合（スマホのカメラ、背景に手や台が写る、
屋外の自然光など）、**そのままでは精度が落ちる可能性が高い**です。

実際に、2010年の別の撮影データにこのモデルの元になった閾値定義を
そのまま当てたところ、A級が1件も出なくなるという失敗が起きています。
撮影条件が変わると鮮紅色画素の絶対量が変わるためです。

### 対処

1. アプリの実際の撮影環境で、人間が等級を判定済みのサンプル写真を
   最低でも各等級20枚程度集める
2. `mango_grader.calibrate_thresholds(image_paths, human_grades)` で
   `a_thr` / `h_thr` を撮影環境向けに選び直す
3. 新しい閾値で `extract_features` を実行し直し、
   `LogisticRegression` を再学習する（`mango_grader_model.joblib` を作り直す）

較正済みモデルができるまでは、`needs_review` の閾値を厳しめ
（`confidence_threshold` を0.7程度に上げる）にして、
判定結果を人が必ず確認する運用を推奨します。

## このモデルにできないこと

- **傷・ヤニによる格下げは判定しません。** JA基準では表面の着色が良くても
  傷やヤニがあれば下位等級に格下げされますが、このモデルは着色（表面等級）
  しか見ていません。表面等級の精度は94.9%相当でも、傷・ヤニ込みの
  最終等級との一致は69%程度に落ちます。実運用では「機械が着色を判定し、
  傷・ヤニは人が最終確認する」という分業を前提にしてください。

- **C級の判定精度は未知数に近いです。** 学習データにC級が3枚しかなく、
  検証結果（正解率100%）はサンプル数の少なさによる見かけ上の高さの
  可能性があります。C級を大量に判定する用途では別途検証してください。

## 学習データについて（重要な変更）

このモデルは、2019年撮影178枚のうち**傷・ヤニ・その他の理由による格下げが
一切ない114枚（color_only サブセット）だけ**で学習しています。

| カテゴリ | 枚数 | 学習に使うか |
|---|---|---|
| **color_only**（傷ヤニなし・表面等級=最終結果） | 114 | ○ 使用 |
| kizu_yani（傷・ヤニあり） | 54 | × 除外 |
| other_demotion（傷ヤニ無いが理由不明の降格） | 10 | × 除外 |

以前のバージョンは178枚全部（傷・ヤニで下がった個体も含む）で学習していましたが、
それだと「傷で下がった果実の色」を、その等級の色として学習してしまい、
純粋な色の判定器としてはノイズでした。114枚版は数値上の交差検証スコアは
やや下がります（旧: macroF1 0.744 → 新: 0.701）が、これは**評価がより正直に
なった**結果です。B級が11枚・C級が3枚と少ないため、5分割交差検証でのばらつきが
大きい点は留意してください。

## 既知の不具合と修正（v1公開前に発見）

較正・検証の過程で、**鮮紅色画素が皆無の果実（緑一色など）を誤ってB判定する
不具合**が見つかりました。学習データに「鮮紅色0%」の個体が一度も無かったため、
ロジスティック回帰がその領域で外挿し、暴れていたのが原因です。

`MangoGrader.predict()` に、鮮紅色画素が検出できない場合（`blob_n == 0`）は
機械学習モデルを介さず直接Cと判定するルールベースのガードを追加して修正済みです。
JA基準でも鮮紅色0%はC以外にありえないため、この上書きは安全です。
新しい撮影環境で `calibrate_thresholds()` を使う場合も、この種の
「学習データに存在しない極端な入力」には注意してください。

## みんなに使ってもらいながら再学習する仕組み

このモデルは配布して終わりではなく、**アプリの利用データを使って
継続的に再学習する**ことを想定しています。3つの部品があります。

### 1. 予測のログを残す（`log_prediction`）

アプリが判定を返すたびに呼んでください。画像もコピーして保存されます。

```python
from mango_grader import log_prediction

result = grader.predict("photo.jpg")
log_id = log_prediction(result, "photo.jpg", user_id="user_123")
```

`feedback_log/log.jsonl` に1件1行で溜まっていきます。

### 2. 人の訂正を記録する（`record_correction`）

ユーザーやスタッフが「これは違う、本当はB」と直したときに呼びます。
**ここが再学習の質を決める一番大事な部分です。**

```python
from mango_grader import record_correction

record_correction(log_id, human_grade="B", source="app_user")
```

`source` は誰が訂正したかの記録です。アプリの一般ユーザーによる訂正
（`"app_user"`）と、専門家による確認（`"expert_review"`）を区別できるように
してあります。

### 3. 定期的に再学習する（`retrain.py`）

```bash
python retrain.py
```

元の178枚 + 訂正が付いたフィードバックだけをまとめて再学習します。
**訂正の付いていない予測（誰も確認していないもの）は学習に使いません。**
機械の判定をそのまま正解として学習すると、モデルが自分の誤りを
強化してしまうためです。

新モデルは自動的に交差検証され、**旧モデルより明らかに悪化していたら
採用せずに警告するだけ**で止まります（既定の閾値はmacro-F1で0.02）。
採用された場合、旧モデルは `mango_grader_model.v{n}.joblib` として
残るので、いつでもロールバックできます。モデルの `meta` には
バージョン・学習日・使ったデータ件数が記録されます
（`grader.version` で確認可能）。

### 運用上の注意

- **等級の不均衡に注意してください。** 元データもC級はわずか3枚しか
  なく、集まったフィードバックもA級に偏りやすいはずです。
  `retrain.py` は等級ごとの件数が0件だと警告しますが、少数でも
  学習には使ってしまうので、時々件数を確認してください。
- **同じ果実を何度も撮った画像が紛れ込むと、交差検証の精度が
  実力より高く出ます。** 短時間に同じユーザーから届いた似た画像は
  重複として扱うことを検討してください。
- 画像は `feedback_log/images/` にそのまま保存されます。個人が写り込む
  ような撮影のさせ方をさせない運用にしてください。

## 性能（参考・2019年データ color_only サブセットでの交差検証）

| 指標 | 値 |
|---|---|
| 正解率 | 92.9% |
| macro-F1 | 0.701 |
| Cohen's kappa | 0.719 |

学習データはA100/B11/C3と不均衡です。特にB・C級は交差検証の各foldで
テスト側が数枚しか無く、スコアの分散が大きい点に注意してください。
継続学習でB級・C級のcolor_onlyサンプル（傷ヤニなし）を増やすことを
最優先にしてください。

## 選択的予測の目安

判定確率の低い個体を人の確認に回すと精度が上がります。

| 自動化率 | 正解率 |
|---|---|
| 100% | 95.5% |
| 90% | 98.1% |
| 80% | 99.3% |
| 60% | 100% |

アプリのUIでは `confidence` が低い（目安 0.55〜0.7未満）判定を
「要確認」として表示し、ワンタップで人の判定に切り替えられる
ようにすることを推奨します。
