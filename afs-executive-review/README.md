# AI FES 役員審査ツール

AFS（AI FES）の**役員審査**フェーズ向けの、1ファイル完結・オフライン動作のExcel取込型審査ツール一式です。
デビューライブ向けツール（`debut-live/` ブランチ）とは対象ユーザー・審査フローが異なるため、
別ブランチ（`claude/afs-executive-review-tool`）として分離管理しています。

このブランチには**実データ（応募者名・部署・提出物リンク・審査員名・AI講評など）は一切含めていません**。
テンプレート・成果物（`dist/`・`build/`）は git 管理外（`.gitignore` 参照）とし、ローカルの作業ディレクトリでのみ扱う運用です。

## 全体の流れ

1. **審査員フェーズ**：各競技の審査員が、担当エントリーを観点別ルーブリックで採点し、
   Excel（`10_役員向け審査シート`）として書き出す
2. **役員フェーズ（このツール）**：役員は審査員の採点結果を参考値として閲覧しながら、
   受賞順位・受賞理由・役員講評・激励コメントを入力する。**採点そのものは役員は編集しない**
3. 役員が「Excelを書き出して提出」すると、事務局へ受賞結果が渡る

同じ競技を複数名の役員が独立に審査する運用があり、その場合は1つの採点結果Excelを
複数の役員ファイルへ共通で取り込む。

## ディレクトリ構成

```
afs-executive-review/
  dist/    … （git管理外）役員に配布する最終ファイル。採点結果を埋め込み済み・開くだけで使える
  build/   … （git管理外）採点結果が未取込のテンプレート。ENTRIES/JUDGEデータを埋め込み済み
  tools/   … （git管理下）Excel取込の自動化・修正スクリプト。実データは含まない
```

`build/` のテンプレートに `tools/bake_scores.js` で採点結果Excelを焼き込むと `dist/` の
最終ファイルが生成できる。`dist/`・`build/` はそれぞれ実データを含むため git には含めず、
必要な開催回ごとにローカルで用意する。

## 使い方（役員側）

1. `dist/` の該当ファイルをブラウザで開く（開くだけでAI事前採点が表示される）
2. 一覧から作品を選び、詳細カードで判断軸・提出物・審査員の採点を確認
3. 「Copilot に読ませる」のA/Bボタンで、任意にCopilotへ相談用プロンプトをコピーできる
   （※点数を書き換える「取り込み」機能は役員配布版では無効化してある。事務局・審査員専用の機能）
4. STEP 1〜3で受賞順位・受賞理由・講評・激励コメントを入力
5. 「Excelを書き出して提出」で事務局へ

## 採点結果Excelの焼き込み（事務局・開発側）

審査員から新しい採点結果Excel（`10_役員向け審査シート`シート、`EntryCode`＋観点①〜④スコア＋
`RubricTotal`＋`Recommend`などの列）を受け取ったら、以下で `dist/` を更新する。

```bash
NODE_PATH=/opt/node22/lib/node_modules node tools/bake_scores.js \
  build/<競技>_<役員名>.html \
  path/to/採点済み.xlsx \
  dist/<出力ファイル名>.html
```

`build/` の各テンプレートは `let aiData = {};` が未取込のプレースホルダーになっており、
`bake_scores.js` はヘッドレスブラウザでテンプレートの「読み込む（Excel）」機能
（`#fileIn` への `setInputFiles`）をそのまま使って取込み、結果を `aiData`/`opsData` として
HTMLに直接埋め込み直す。取込ロジック自体（`importAI()`）はテンプレート側にあるため、
このスクリプトは重複実装していない。

同じ競技を複数の役員が担当する場合、同じExcelをそれぞれの役員テンプレートに焼き込む必要がある。
`AgentKey（採点主体）`列が無いExcelの場合、シート内の全件がそのまま各ファイルに取り込まれる
（審査員ごとの絞り込みは行われない）。

### AI講評中の審査員名の置換

1つの採点結果Excelを複数の役員ファイルへ取り込む場合、講評文中に採点時の審査員名
（例：「最終判断は◯◯さんご自身へ」）がそのまま残ることがある。焼き込み後に以下で
汎用的な「あなた」へ置換する（対象の実名リストは `tools/fix_review_names.py` 内で管理）。

```bash
python3 tools/fix_review_names.py dist/*.html
```

### 検証

```bash
NODE_PATH=/opt/node22/lib/node_modules node tools/verify.js dist/*.html
```

以下を確認する：
- ENTRIES件数・AI事前採点の取込件数
- 受賞順位が全件空欄（役員が未入力の状態で配布されているか）
- Copilotの「取り込み」機能が非表示になっているか（役員配布版のみ）
- 初回ヘルプが自動表示されるか
- JSエラーが出ていないか

## 役員配布版で無効化している機能

役員は採点結果を**編集しない**（審査員の役割）という設計方針のもと、以下を役員配布版のみ
非表示にしている（テンプレートCSSで `.cp-step-import` と `#btnCopilot` を `display:none` に
している）：

- 各作品カードの「✓ 採点結果をこの作品に取り込む」（Copilot出力を貼り付けて点数を書き換える機能）
- ツールバーの「Copilot採点を取り込む」（一括取込）

一方、**採点プロンプトをコピーする機能（A/B）は残している**（点数を書き換えない、参考にする
だけの機能のため）。

## HTML加点について

作品ファイルがHTML形式で提出されていても、**このツールでは加点は行わない**
（`BONUS_PER_FILE = 0` / `MAX_BONUS = 0`）。審査員側の採点結果Excelに古い加点ルール
（作品+5／手順書+5）が残っていても、取込時に `RubricTotal` を優先して使うため影響を受けない。

## 既知の制約・今後の課題

- `build/` のテンプレートは、実データ（ENTRIES・JUDGEプロンプト・ルーブリック）を直接埋め込んだ
  スナップショットであり、開催回ごとに使い回せる汎用ビルドスクリプト（`debut-live/build/build.py`
  相当）にはまだ整理できていない。次回以降の開催で使う場合は、マスターExcelからENTRIES/JUDGEデータを
  都度生成するスクリプトに切り出すことを検討する
- 自動テスト（Playwright回帰テスト）は `tools/verify.js` の簡易チェックのみで、
  `debut-live/` のような網羅的なテストスイートはまだ無い
