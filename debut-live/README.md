# AI FES 2026 デビューライブ 受賞選定ツール

AFS役員審査ツールと同じ「1ファイル完結・オフライン動作」の設計を踏襲した、**デビューライブ用の内部スタッフ向け受賞選定ツール**です。役員による選出は行わず、**ルーブリック採点＋いいね加点＋HTML加点の自動集計で上位6件を毎月選出**します。

配布物は3本です。どれもダブルクリックしてブラウザ（Edge / Chrome）で開くだけで動作し、ネット接続やサーバーは不要です。

| ファイル | 用途 |
|---|---|
| `dist/AIFES2026_デビューライブ_受賞選定ツール.html` | 作業者がデビューライブの受賞候補を選定する（1人1ファイルで入力・書き出し） |
| `dist/AIFES2026_デビューライブ_受賞突合ツール.html` | 事務局が、複数の作業者が書き出したExcelを突合して最終版を1本にまとめる |
| `dist/AIFES2026_自動集計競技_受賞選定ツール.html` | 自動集計競技（Buzz / シーンメーカー / クルーアワード）を1本で扱う。競技タブで切り替え |

デビューライブは2人の作業者が別々に選定し、後で突合ツールで照らし合わせる運用を想定しています。自動集計競技は集計がほぼ自動なので、原則1人で確認・書き出しできます（設計の詳細は `in/06_自動集計競技.md`）。

## AFS役員審査ツールとの違い

| | AFS役員審査 | デビューライブ |
|---|---|---|
| 選ぶ人 | 役員が3件ずつ選出（合議なし） | いない。スコア自動集計で上位6件を選出 |
| ツール数 | 役員6名分＝6ファイル | 1本（内部スタッフ用） |
| いいね | 参考表示のみ、スコア対象外 | **スコアの3本柱の1つ**（もらった数＋押した数をそのまま加点、もらう上限+25／押す上限+15＝合計上限+40） |
| 開催サイクル | 通期で1回 | **月次**。毎月上位6名 |
| 連続受賞 | 運営が個別に「連覇除外」を設定 | **仕組みとして必須**：一度受賞したら以降の月は対象外 |

## 最終スコア

```
最終スコア = ルーブリック（4指標・100点満点）
           + いいね加点（もらったいいね数そのまま上限 +25 ＋ 押したいいね数そのまま上限 +15 ＝ 合計上限 +40）
           + HTML加点（作品ファイルHTML→+5／手順書ファイルHTML→+5、上限 +10）
```

- **ルーブリック点数は内部スタッフが画面で直接入力します**。一覧の観点①〜④の枠に 0〜10 点を入力すると `Σ(点÷10×25)` で100点満点に換算され、最終スコア・順位が即時に再計算されます。採点マスターにAI採点が入っていればそれを初期値として表示し、上書きできます（採点方法は書き出しExcelに「AI／手動」で記録されます）
- ルーブリックは `in/05_デビューライブ.md` を参照（核心思想「ハードルを乗り越えた初体験を語れる人」、4指標×25%×満点10。各指標の 2/5/8/10 点の目安は画面下部およびツール本体にも表示されます）
- いいね加点は `03_いいね集計`（＝`16_デビュー抽出`）の `LikesReceived（もらう）`（上限+25）と `LikesGiven（押す）`（上限+15）の**生の件数をそのまま加点**し、それぞれの上限で頭打ちします（合計上限+40）。`LikesGiven（押す）` は投稿者単位の値のため、同一応募者の各エントリーに同じ値が付きます
- 同点時の優先順位：① ルーブリック生点が高い方 → ② いいね数が多い方 → ③ スタッフが手動で順位を入れ替え

## 運用ドキュメント（審査オペレーション全体設計）との差分

既存の運用ドキュメント『AI Fes 2026 ― 審査オペレーション全体設計』にはデビューライブの取り決めが記載されていますが、本ツールのデビューライブ仕様は、その後の運用側との協議で確定した内容が優先されます（2026-07時点で確定）。運用ドキュメントと本ツールで異なる点は以下の通りで、**デビューライブについては本ツールが最新の正**です。

| 論点 | 本ツール（最新・正） | 運用ドキュメント（旧） |
|---|---|---|
| 前月受賞者 | 複数回受賞なし（過去受賞者を除外） | R-11：毎月リセット・前月受賞者も翌月対象 |
| 受賞の単位 | 全体で最終スコア上位6件（フラット） | 金銀銅×2部門（Copilot／マルチAI）＝6名/回 |
| スコア式 | ルーブリック100＋もらういいね(上限25)＋押すいいね(上限15)＋HTML加点(上限10) | AI採点40＋もらういいね25＋利用頻度申告20＋押すいいね15＝100点 |
| 同点時の第2優先 | いいね数が多い方 | エントリー日時が早い方 |

運用ドキュメントを改訂する際は、上記に合わせてデビューライブの節を更新してください。

## 使い方（受賞選定ツール／作業者ごと）

1. `dist/AIFES2026_デビューライブ_受賞選定ツール.html` をブラウザで開く
2. 右上「作業者名」に自分の名前、「対象月」に `2026年7月` のように入力
3. 「採点マスターExcelを読み込む」で、エントリー一覧（列構成は下記）を読み込む
4. **一覧の観点①〜④の枠にルーブリック点数（0〜10）を入力する**。枠にカーソルを合わせると各点（2/5/8/10）の目安が表示される。入力すると最終スコアが即時計算され、上位6件が自動で受賞候補になる（金色のカード）。AI採点が入っていれば初期値として表示されるので、必要なら上書きする
5. 前月までに書き出した「受賞一覧Excel」があれば「過去の受賞者Excelを追加」にドロップする
   - その受賞者は今月の対象から自動的に除外され、行が淡色化・順位選択不可になる
   - 複数月分をまとめて追加できる
7. 受賞候補カードのプルダウンで、必要なら順位を手動で固定・入れ替える（誤検知・欠損対応）。一覧表の各行の「順位」プルダウンからも同様に変更できる。手動で固定した順位はそのまま残り、それ以外の枠は現在のスコアで自動補充される
8. 各受賞候補カードに受賞理由・講評コメントを記入する
9. 「入力チェック」で作業者名・ルーブリック点数・受賞理由の記入漏れ等を確認
10. 「Excelを書き出して提出」→ `受賞一覧`シート（作業者名・観点①〜④スコア・採点方法の列入り。次月の除外リストとしてそのまま再利用可）と `全エントリー`シート（参考・監査用）が入ったExcelが出力される

入力内容（作業者名・対象月ごとのルーブリック点数・受賞順位・受賞理由・講評コメント・除外リスト）はブラウザのlocalStorageに自動保存されます。閉じて開き直しても残ります。「入力を全消去」でその作業者・対象月分だけ消せます。

2人で作業する場合は、それぞれ別の「作業者名」でこの手順を独立に行い、それぞれExcelを書き出してください。

## 使い方（受賞突合ツール／事務局）

1. `dist/AIFES2026_デビューライブ_受賞突合ツール.html` をブラウザで開く
2. 2人（以上）の作業者が書き出したExcelをまとめてドロップする
3. 順位ごとに全員の選出結果を比較表示：
   - **一致**：全員が同じ作品を選んでいれば緑色。受賞理由・講評コメントの文言だけ違う場合は、それぞれの文言を「田中の文言」のようなボタンでワンクリック採用できる
   - **不一致**：順位ごとに違う作品が選ばれていれば赤色。ラジオボタンでどちらを採用するか選ぶ（候補にない作品を手動指定することも可能）
4. 「スコア不一致チェック」で、同じ作品なのに作業者間でスコアが違う箇所も検出する（マスターExcelの版が違う可能性の手がかりになる）
5. 「確定チェック」で未確定の順位が残っていないか確認し、「最終版Excelを書き出す」で確定した`受賞一覧`を1本のExcelとして出力する

## 使い方（自動集計競技ツール／Buzz・シーンメーカー・クルーアワード）

AI採点もルーブリックも無い自動集計型の3競技を1本で扱います。設計の詳細は `in/06_自動集計競技.md`。

1. `dist/AIFES2026_自動集計競技_受賞選定ツール.html` をブラウザで開く
2. 上部のタブで競技を選ぶ（Buzz / シーンメーカー / クルーアワード）。右上に作業者名・期（中間/最終など）を入力
3. 「マスターExcelを読み込む」で集計マスター（`01_EntryINDEX` ＋ `03_いいね集計` を含む）を読み込む。人ごとに自動集計され、上位6名が受賞候補になる
   - **Buzz**：buzz投稿の被いいねを人ごとに合計。同点は 平均いいね → 投稿数
   - **シーンメーカー**：`IsSceneEligible` の人の、全競技横断の通期累計いいね。対象が6名未満なら該当者のみ
   - **クルーアワード**：支援アンバサダー名の記載数。**名寄せパネル**で表記ゆれ（`色部 晟洋`＝`色部さん`）を「統合先」に同じ正式名で入力してまとめ、ゴミ入力は「無効」にチェックしてから集計する。改行・カンマ区切りの複数名は自動分割される
4. 同じ競技の過去受賞者を除外したい場合（Buzzの中間→最終など）は「過去の受賞者Excelを追加」にドロップする。マスターに `04_受賞者マスタ` があれば、その競技の行を自動反映する。**競技をまたいだ除外はしない**（発信・継続・支援は別物なので重複受賞OK）
5. 必要なら受賞候補カード／一覧の順位プルダウンで手動固定・入れ替え（固定した順位は残り、他はスコアで自動補充）
6. 「入力チェック」→「Excelを書き出して提出」で `受賞一覧`＋`全対象者`シートを出力する

入力（作業者名・期・順位固定・名寄せ・備考・除外）は競技×期ごとにブラウザへ自動保存されます。

## 採点マスターExcelの読み込み方

実際の集計マスター（`01_EntryINDEX` / `02_採点結果台帳` / `03_いいね集計` / `16_デビュー抽出` / `04_受賞者マスタ` などを含む大きなワークブック）をそのまま読み込めます。列名は実データのExcel（`16_デビュー抽出`シート・`02_採点結果台帳`シート）の命名にそのまま合わせてあります。

**エントリー一覧＋いいね数の読み込み**（優先順）
1. シート名に「デビュー抽出」を含み `EntryCode` 列があるシート（＝`16_デビュー抽出`）
2. 無ければ、`EntryCode` と（`応募者・部署` または `SubmitterDisplayName`）と（`いいね（もらう）` または `LikesReceived（もらう）`）を持つ最初のシート（例：`03_いいね集計`）。この場合 `CompetitionKey` 列があれば `debut` 以外の行、`IsHidden`＝`True` の行、`Status` が `Published` 以外の行を自動的に除外する

**ルーブリック点数（採点）の扱い**
- ルーブリック点数は原則としてスタッフが画面で入力します（上記「使い方」参照）。
- 採点マスターにAI採点が入っている場合は、それを初期値として読み込みます：`EntryCode`・`観点①スコア`が上記と同じシートに無い場合、`EntryCode`・`CompetitionKey`・`観点①スコア`を持つシート（＝`02_採点結果台帳`）から `CompetitionKey = debut` の行だけを抽出し、`EntryCode` で結合します。
- 結合できず、かつ画面でも未入力のエントリーは「未採点」として扱い、一覧には出るが受賞候補の対象外になります。**1件も採点されていない場合は入力チェックでエラーになり、受賞候補の自動選出も行われません**（＝点数を入力すると選出が始まります）。

**主な列の対応**

| 内容 | 列名（候補） |
|---|---|
| エントリーコード | `EntryCode`（必須） |
| 対象月 | `対象月`、無ければ `PeriodKey`（例：`debut-cool1`。あれば自動で「対象月」欄に反映） |
| 応募者・部署 | `応募者・部署`、無ければ `SubmitterDisplayName` + `Department` から組み立てる |
| 応募者の一意キー | `SubmitterUserKey` / `SubmitterEntraId`（`04_受賞者マスタ`との突合に使用） |
| 作品リンク | `作品リンク`、無ければ `PrimaryFileUrl`。未入力なら「資料欠損」扱いで受賞対象外 |
| 手順書リンク | `ProcedureFileUrl` |
| ルーブリック4指標 | `観点①スコア`〜`観点④スコア`（各0〜10点） |
| ファイル形式・HTML加点 | 明示的な `作品ファイル形式`/`手順書ファイル形式` 列があれば優先。無ければ作品リンク・手順書リンクのURL拡張子（`.html`→HTML扱い）から自動判定してそれぞれ+5点 |
| いいね（もらう） | `いいね（もらう）`、無ければ `LikesReceived（もらう）`（生の値。上限+25はツール側で適用） |
| いいね（押す） | `いいね（押す）`、無ければ `LikesGiven（押す）`（生の値。上限+15はツール側で適用。列が無ければ0点扱い） |

`RubricTotal`（ルーブリック合計）列が無ければ、4指標から `Σ(獲得点÷10×25)` で自動計算します。

**過去受賞者の除外（04_受賞者マスタ）**

採点マスターに `受賞者（本人）`・`CompetitionKey`・`PeriodKey` を持つシート（＝`04_受賞者マスタ`）が含まれている場合、`CompetitionKey = debut` の行を自動的に読み込み、`SubmitterEntraId` があれば今回のエントリーと突合して（無ければ氏名で）除外に反映します。「過去の受賞者Excelを追加」でドロップする方式と併用でき、両方の結果が合算されます。

## ビルド方法（開発者向け）

`dist/` の配布ファイルは、`build/template.html`（デビュー受賞選定）・`build/template_reconcile.html`（デビュー受賞突合）・`build/template_auto.html`（自動集計競技）にそれぞれ SheetJS（`build/package/dist/xlsx.mini.min.js`）を埋め込んで生成しています。ツールのロジックを変更する場合は対象の `build/template*.html` を編集し、以下を実行してください（3本まとめてビルドされます）。

```
cd build
python3 build.py
```

## テスト・ダミーデータ

`dummy/` に検証用の一式があります。生成される派生ファイル（`master_test*.xlsx` / `staffA.xlsx` / `staffB.xlsx` など）は `.gitignore` 対象なので、テスト前に生成し直してください。

```
cd dummy
python3 make_dummy.py               # ダミーの採点マスター(15件・単一シート形式)・前月受賞一覧(2名)・突合テスト用マスター違いを生成
python3 make_dummy_real_shape.py    # 実データのシート構成（16_デビュー抽出／02_採点結果台帳／04_受賞者マスタが別シート）を模したダミーを生成
python3 make_dummy_auto.py          # 自動集計競技（01_EntryINDEX／03_いいね集計／04_受賞者マスタ）を模したダミーを生成
NODE_PATH=/opt/node22/lib/node_modules node test_tool.js               # デビュー受賞選定ツールの回帰テスト（単一シート形式）
NODE_PATH=/opt/node22/lib/node_modules node test_real_shape.js         # デビュー受賞選定ツールの回帰テスト（実データのシート構成）
NODE_PATH=/opt/node22/lib/node_modules node test_manual_scoring.js     # 画面でのルーブリック手動採点→自動ランキング→書き出しの回帰テスト
NODE_PATH=/opt/node22/lib/node_modules node test_auto.js               # 自動集計競技ツール（Buzz/シーン/クルー）の回帰テスト
NODE_PATH=/opt/node22/lib/node_modules node gen_two_staff_exports.js   # 2人の作業者が独立入力した想定のExcelを2本生成
NODE_PATH=/opt/node22/lib/node_modules node test_reconcile.js          # デビュー受賞突合ツールの回帰テスト
```

- `test_tool.js` は以下を検証します：採点マスターの読み込み、最終スコアの自動算出とランキング、資料欠損の除外、過去受賞者Excelによる除外、順位の手動オーバーライド（重複なく入れ替わること）、入力チェック、Excel書き出し、JSエラーが出ないこと。
- `test_real_shape.js` は以下を検証します：`16_デビュー抽出`＋`02_採点結果台帳`＋`04_受賞者マスタ`が別シートの場合の読み込み・結合、他競技（CompetitionKey違い）や非公開（IsHidden）エントリーの除外、一部エントリーが未採点の場合の扱い、`04_受賞者マスタ`のSubmitterEntraIdでの突合、URL拡張子からのHTML加点判定、JSエラーが出ないこと。
- `test_manual_scoring.js` は以下を検証します：未採点エントリーの観点①〜④を画面で入力するとルーブリック・最終スコアが自動計算されること、満点にすると受賞候補に入ること、点数を消すと未採点に戻ること、入力した点数と「採点方法＝手動」が書き出しExcelに反映されること、JSエラーが出ないこと。
- `test_reconcile.js` は以下を検証します：2人分のExcelの読み込み、一致／不一致判定、不一致順位でのラジオボタン選択、一致順位での受賞理由クイックフィル、マスターExcelの版違いによるスコア不一致検知、確定版Excelの書き出し、JSエラーが出ないこと。
- `test_auto.js` は以下を検証します：Buzzの人ごとの被いいね合計・上位選出・`04_受賞者マスタ`による同競技受賞者の除外、シーンメーカーの全競技横断の通期累計いいね集計、クルーアワードの名寄せ（表記ゆれの統合で記載数が合算されること・ゴミ入力の無効化）、各競技のExcel書き出し、JSエラーが出ないこと。

実際の集計マスターを使って手動確認したい場合は、社外に出せない実データを含むため `dummy/real/`（`.gitignore`対象）のような場所に置いて個別に確認してください。
