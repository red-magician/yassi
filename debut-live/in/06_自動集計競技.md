# AI FES 2026 自動集計競技 ― 設計フロー（Buzz / シーンメーカー / クルーアワード）

> デビューライブ受賞選定ツールに続く、**AI採点なし・自動集計型**の3競技の設計文書。
> 実装（1本の自動集計ツール・競技切替）に入る前の合意用ドラフト。
> 前提：ツール構成＝1本にまとめて競技切替／シーンメーカー＝全競技横断の通期累計いいね／クルー＝手動マージUIで名寄せ／Buzz＝中間受賞者を最終で除外。

---

## 0. 位置づけ

『審査オペレーション全体設計』で **①自動集計型（AI採点なし）** に分類される競技のうち、Buzz・シーンメーカー・クルーアワードの3つを、実データ（マスターExcel）に接続して回せる形に落とし込む。アンコールも同じ類型だが今回のスコープ外（必要なら同じツールにモード追加で対応可能）。

デビューライブとの根本的な違い：

| | デビューライブ | この3競技 |
|---|---|---|
| 採点 | ルーブリック（スタッフが点数入力） | **なし**。数値は集計で自動的に決まる |
| 主なスタッフ作業 | 点数入力・受賞理由 | **集計元の確認・名寄せ・対象の妥当性チェック** |
| スコア | ルーブリック＋いいね＋HTML | **単一の集計値**（いいね数 or 記載数）のみ |
| 役員/AI | AIは初期値のみ | 一切関与しない |

---

## 1. 全体像 ― 3競技は「人ごとに数える → 上位6名」

3競技はすべて「**ある数値を人ごとに集計し、降順で上位6名を表彰**」という同じ骨格。違うのは「何を数えるか」と「対象者の条件」だけ。

```
競技を選ぶ  →  マスターExcelを読み込む  →  ツールが人ごとに自動集計
   →  （クルーのみ）名前の表記ゆれをスタッフが手動でまとめる
   →  上位6名が自動で受賞候補  →  必要なら手動で順位を補正
   →  Excelを書き出す
```

---

## 2. 共通フロー（6ステップ）

| STEP | 内容 | 担当 |
|---|---|---|
| ① 競技選択 | Buzz / シーンメーカー / クルーアワード を切り替える | スタッフ |
| ② 読み込み | マスターExcelを読み込み、対象エントリーを抽出 | ツール |
| ③ 集計 | 人ごとに「いいね数」または「記載数」を合計 | ツール |
| ④ 名寄せ | （クルーのみ）表記ゆれ・あだ名・複数名セルを1人に統合 | スタッフ |
| ⑤ 順位付け | 集計値の降順＋タイブレークで上位6名を自動選出 | ツール |
| ⑥ 補正・書き出し | 誤りがあれば手動で順位を固定・除外し、Excelを書き出す | スタッフ |

## 3. 競技別 集計仕様

### 3-1. Buzzステージ
- **核心思想**：先駆者として情報発信し続ける人
- **対象**：`CompetitionKey = buzz` かつ `IsBuzzEligible = TRUE`（審査対象フラグが立っているもの）
- **集計**：人ごとに、buzz投稿の **`LikesReceived（もらう）` を合計**
- **順位**：合計いいね数の降順
- **タイブレーク**：① 1投稿あたり平均いいね（合計 ÷ 投稿数） → ② 投稿数が多い方
- **周期**：中間（7月末）＋最終（9月末）の2回。**中間受賞者は最終の対象から除外**
- **表彰**：6名／回
- 実データ（7月）：45投稿 → 11人。例）Funakoshi 61（4投稿/平均15.2）、Akamine 39（1投稿/平均39.0）。平均タイブレークが効くケースあり（Nishino 42いいねだが25投稿・平均1.7）。

### 3-2. シーンメーカー
- **核心思想**：半年間継続発信し続けたアンバサダー・先駆者
- **対象**：`IsSceneEligible = TRUE` の人
- **集計**：その人の **6〜9月・全競技横断の `LikesReceived（もらう）` 累計**（scene投稿だけでなく、その人があらゆる競技で得たいいねの合計）
- **順位**：累計いいね数の降順
- **タイブレーク**：① 平均いいね → ② 投稿数
- **周期**：最終（9月末）1回
- **表彰**：6名。**対象者が6名に満たない場合は該当者数のみ表彰**（現状データは3名・7月分のみ＝通期が揃うと増える想定）

### 3-3. クルーアワード
- **核心思想**：他者を支援した結果、名前を書いてもらえる人
- **対象**：全エントリーフォームの `SupportAmbassadorNames` に名前が記載された人
- **集計**：**名寄せ後の人ごとに、名前が記載されたエントリー数をカウント**（1エントリーに複数名記載 → 各名に +1）
- **順位**：記載数の降順
- **タイブレーク**：① 複数部署・複数競技にまたがって記載 → ② エントリー数の多い競技からの記載
- **周期**：最終（9月末）1回
- **表彰**：6名
- 実データ（7月）：57件記載・生の名前28種。**要名寄せ**（下記5章）。

## 4. データソース（列マッピング）

読み込むシートと列（実データのマスターExcel準拠。列名は別名も許容）。

| 用途 | シート | 主な列 |
|---|---|---|
| エントリー基本・対象フラグ・支援者名 | `01_EntryINDEX` | `EntryCode` / `CompetitionKey` / `PeriodKey` / `SubmitterDisplayName` / `SubmitterEmail` / `SubmitterEntraId` / `Department` / `IsBuzzEligible` / `IsSceneEligible` / `SupportAmbassadorNames` / `審査対象フラグ` |
| いいね数（もらう） | `03_いいね集計` | `EntryCode` / `SubmitterUserKey` / `SubmitterDisplayName` / `LikesReceived（もらう）` |
| 過去受賞（重複除外） | `04_受賞者マスタ` | `SubmitterEntraId` / `受賞者（本人）` / `CompetitionKey` / `PeriodKey` |

- **人の同定キー**：`SubmitterEntraId`（無ければ `SubmitterEmail` を小文字化・前後空白除去、それも無ければ表示名）。デビューライブツールと同じ考え方。
- 自己いいね：データ側で `自己リアクション行数 = 0` 処理済みのため、ツールでは考慮不要。
- いいねの上限（デビューの +25）：**この3競技には設けない**（いいね数そのものが順位のため、上限で頭打ちにすると順位が潰れる）。

## 5. 名寄せ手順（クルーアワードのみ）

`SupportAmbassadorNames` は自由記述で品質が低い（1セルに改行区切りで複数名、表記ゆれ、あだ名、打ち間違いのゴミ）。そこで2段階で処理する。

**ツールが自動でやること**
1. 各セルを **改行・カンマ・スラッシュ**で分割 → 前後空白除去
2. 出現した名前を一意化し、「生の名前」ごとの記載数を仮集計して一覧表示

**スタッフが手動でやること（名寄せUI）**
3. 表記ゆれを1人に**マージ**（例：`色部 晟洋` ＝ `色部さん`、`ぺぺ` ＝ 実名）。マージ後の正式表記を1つ選ぶ
4. 無効な入力（キーボード打ち間違いのゴミ文字列など）を**除外**指定
5. マージ・除外を反映して記載数を再集計 → 順位確定

名寄せの結果（どの生名をどの人に統合したか）は書き出しExcelにも残し、監査できるようにする。

## 7. 重複・複数回受賞の制御

- **Buzz（中間→最終）**：中間（7月末）の受賞者は、最終（9月末）の集計対象から自動除外する。→ 過去に書き出した「中間の受賞一覧Excel」または `04_受賞者マスタ` を読み込んで除外（デビューライブと同じ仕組み）。
- **【要確認・オープン事項】** 質問時に「その他」を選択いただいた分の中身が未確定です。以下のいずれかを想定しています（推奨：A）。ご指定いただければ確定します。
  - **A（推奨・運用ドキュメントR-02準拠）**：この3競技は測るものが別（発信／継続／支援）なので、競技をまたいだ重複受賞は許す。同一競技内でのみ複数回受賞なし（＝Buzz中間→最終除外のみ）。
  - **B**：この自動3競技の間でも重複受賞なし（Buzzで受賞したらシーン/クルーの対象外）。
  - **C**：デビュー等も含め全競技横断で重複受賞なし（`04_受賞者マスタ` の全受賞者を除外）。
  - **D**：シーンメーカーは通期の総まとめなので他競技受賞と重複OK、など競技別の例外。

## 8. ツールUI設計（1本・競技切替）

- **ヘッダ**：競技切替（Buzz / シーンメーカー / クルーアワード）／対象月・期（中間・最終）／作業者名／受賞 6/6／対象人数
- **上部：受賞候補6名カード**（デビューライブと同じ操作感）
  - 集計値（いいね数 or 記載数）・平均・投稿数などの内訳を表示
  - 順位のプルダウンで手動固定・入れ替え（固定した順位は残り、他は自動補充）
  - 任意の講評・備考メモ欄（自動競技なので必須にはしない）
- **中部：全対象者テーブル**（人ごとの集計結果）
  - 列：順位／氏名・部署／集計値／平均／投稿数／状態（受賞候補・受賞済み(他期/他競技) など）
  - 並び替え（集計値順・平均順・氏名順）・フィルタ（受賞候補・受賞済み）
- **クルーのみ：名寄せパネル**（テーブルの上）
  - 生の名前一覧と記載数を表示 → ドラッグ or 選択で「同じ人」をまとめる → 正式表記を選ぶ／無効を除外
- **下部**：入力チェック（対象人数不足・名寄せ未処理の生名が残っている 等）／書き出し／印刷／全消去
- 入力（作業者名・順位固定・名寄せ・メモ）はブラウザに自動保存（競技×期ごと）。
